====================================================
DIGITAL PRODUCTS DOWNLOADS MARKETPLACE
FIRST TIME RUN GUIDE
====================================================

1) Open terminal in project root
   cd digital_products_downloads_marketplace

2) Install all dependencies
   npm install
   npm install --prefix frontend
   npm install --prefix backend_service

3) Make sure PostgreSQL is installed and running
   - Install PostgreSQL on your computer
   - Start PostgreSQL server
   - Create database named: digital_product

   Command example:
   psql -U postgres -c "CREATE DATABASE digital_product;"

4) Run database migration
   In pgAdmin:
   - Open database digital_product
   - Query Tool
   - Open file: backend_service\migrations\001_create_user_roles_and_accounts.sql
   - Execute the SQL

   Or from terminal:
   psql -U postgres -d digital_product -f backend_service/migrations/001_create_user_roles_and_accounts.sql

5) Create the backend environment file
   From the project root, copy the template:
   Copy-Item backend_service\.env.example backend_service\.env

   Open the file:
   notepad backend_service\.env

   Put these values in backend_service\.env:
   DB_HOST=localhost
   DB_PORT=5432
   DB_NAME=digital_product
   DB_USER=postgres
   DB_PASSWORD=YOUR_POSTGRES_PASSWORD
   JWT_SECRET=replace-with-a-long-random-secret
   PORT=5000
   GOOGLE_CLIENT_ID=your-google-client-id
   GOOGLE_CLIENT_SECRET=your-google-client-secret
   GOOGLE_CALLBACK_URL=http://localhost:5000/api/auth/google/callback
   FRONTEND_URL=http://localhost:3000
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=587
   SMTP_SECURE=false
   SMTP_USER=your-gmail-address@gmail.com
   SMTP_PASS=your-gmail-app-password
   SMTP_FROM=your-gmail-address@gmail.com
   PASSWORD_RESET_OTP_LENGTH=6
   PASSWORD_RESET_OTP_EXPIRES_MINUTES=15

   Generate a secure JWT secret locally with PowerShell:
   node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"

   Replace the JWT_SECRET value with the generated value.
   Use JWT_SECRET exactly. Do not use WT_SECRET.

    Configure Google OAuth:
    - Open https://console.cloud.google.com/
    - Create or select a Google Cloud project.
    - Configure OAuth consent screen.
    - Create an OAuth Client ID for a Web application.
    - Add this authorized redirect URI exactly:
       http://localhost:5000/api/auth/google/callback
    - Copy the generated client ID and secret into backend_service\.env.
    - Restart the backend after changing .env.

   DB_PASSWORD is used directly by the backend. Special characters are handled by the application.

   Configure Gmail for password reset OTP emails:
   - Enable 2-Step Verification on the Gmail account.
   - Create a Google App Password.
   - Put the 16-character App Password in SMTP_PASS (remove spaces if needed).
   - Never use your normal Gmail password.

6) Run migration from backend
   cd backend_service
   npm.cmd run migrate

   For an existing database, do not run the command above because migration 001 recreates the tables.
   Run only this SQL in pgAdmin Query Tool instead:
   ALTER TABLE "UserAccounts"
      ADD COLUMN IF NOT EXISTS "ResetOtpHash" VARCHAR(64),
      ADD COLUMN IF NOT EXISTS "ResetOtpExpiresAt" TIMESTAMPTZ;

7) Start backend server
   cd backend_service
   npm.cmd run dev

   Backend runs at:
   http://localhost:5000

8) Start frontend server (use a second terminal)
   cd frontend
   npm.cmd run dev

   Frontend runs at:
   http://localhost:3000

9) Start both together from project root
   cd D:\studydocs\Y4S2\ProjectManagementSystem\digital_products_downloads_marketplace
   npm.cmd run dev

10) Useful checks
   - Backend health check:
     http://localhost:5000/

   - Frontend page:
     http://localhost:3000

   - List tables in PostgreSQL:
     \dt

    - Register through the frontend:
       Open http://localhost:3000/register

    - Login through the frontend:
       Open http://localhost:3000/login

    - Forgot password with OTP:
       Open http://localhost:3000/forgot-password.
       Enter the account email and submit the form.
       Check the configured Gmail inbox for the 6-digit OTP.
       Enter the email, OTP, and a new password at the reset screen.
       The OTP expires after 15 minutes and can be used only once.

    - Google login:
       Open http://localhost:3000/login and click Continue with Google.
       The first Google login creates one Buyer account with a NULL PasswordHash.
       Later Google logins reuse the same UserAccounts record through the Google
       ProviderAccountId.

    - Test register API from PowerShell:
       Invoke-RestMethod -Method Post http://localhost:5000/api/auth/register `
          -ContentType "application/json" `
          -Body '{"name":"Test User","email":"test@example.com","password":"Password123!"}'

    - Test login API from PowerShell:
       Invoke-RestMethod -Method Post http://localhost:5000/api/auth/login `
          -ContentType "application/json" `
          -Body '{"email":"test@example.com","password":"Password123!"}'

====================================================
TROUBLESHOOTING
====================================================

If psql is not recognized:
   - Install PostgreSQL and add the bin folder to PATH
   - Example path:
     C:\Program Files\PostgreSQL\16\bin

If password error:
   - Use your actual PostgreSQL username/password in DB_USER and DB_PASSWORD
   - Confirm PostgreSQL is running on DB_HOST and DB_PORT

If authentication says database is not configured:
   - Confirm backend_service\.env exists
   - Confirm it contains DB_HOST, DB_PORT, DB_NAME, DB_USER, and DB_PASSWORD
   - Stop and restart the backend after changing .env

If authentication says JWT_SECRET is missing or invalid:
   - Confirm the variable is spelled JWT_SECRET
   - Generate a new value with the Node command above

If Google login says Google OAuth is not configured:
   - Confirm GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET are in backend_service\.env
   - Confirm the callback URL matches Google Cloud exactly
   - Restart the backend server

If forgot password does not send an OTP:
   - Confirm SMTP_USER is the Gmail address that created the App Password
   - Confirm SMTP_PASS is an App Password, not the normal Gmail password
   - Confirm SMTP_FROM matches SMTP_USER or an allowed sender
   - Restart the backend after changing .env
   - Check the Gmail Spam folder

If migration fails:
   - Check that database digital_product exists
   - Make sure pgcrypto extension is enabled
   - Run the SQL file again in pgAdmin
